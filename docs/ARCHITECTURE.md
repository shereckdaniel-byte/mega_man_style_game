# Technical Architecture

Godot 4.7.x · GDScript · Compatibility renderer · fixed 60 Hz physics

---

## 1. Folder layout

```
res://
├── addons/                     # gdUnit4, any editor plugins
├── assets/
│   ├── sprites/
│   │   ├── player/             # PNG + AutoSprite .json atlas, side by side
│   │   ├── bosses/<name>/
│   │   ├── enemies/<name>/
│   │   ├── effects/
│   │   └── items/
│   ├── tilesets/<stage>/
│   ├── audio/{bgm,sfx}/
│   └── fonts/
├── resources/
│   ├── sprite_frames/          # GENERATED by tools/autosprite_import.gd — do not hand-edit
│   ├── weapons/                # WeaponData .tres, one per weapon
│   ├── enemies/                # EnemyData .tres (hp, contact damage, drop table)
│   └── damage_tables/          # weapon -> entity damage overrides
├── scenes/
│   ├── actors/{player,bosses,enemies}/
│   ├── projectiles/
│   ├── level/                  # Room, Door, Checkpoint, Ladder, MovingPlatform, gimmicks
│   ├── ui/                     # HUD, WeaponMenu, StageSelect, Title, WeaponGet
│   └── stages/<stage>/
├── scripts/
│   ├── autoload/
│   ├── core/                   # StateMachine, State, Hurtbox, Hitbox, Health, DamageInfo
│   └── util/
├── tools/                      # EditorScripts: autosprite_import.gd, tileset_build.gd
└── tests/
```

Rule: **`resources/sprite_frames/` is build output.** It is committed (so the project opens
without running tools) but regenerated, never edited by hand.

| --- | --- | --- |

| `display/window/size/viewport_height` | `224` | NES visible height (240 minus overscan) |

| `display/window/stretch/scale_mode` | `integer` | no shimmer on scroll |

| `rendering/2d/snap/snap_2d_transforms_to_pixel` | `true` | no sub-pixel sprite wobble |
| `rendering/2d/snap/snap_2d_vertices_to_pixel` | `true` | |

## 3. Movement constants

Authored in **pixels per frame** at 60 Hz — the units the original hardware used — and
converted once at load. Keep them in one `PlayerTuning` resource so they are inspectable
and testable.

```gdscript
# scripts/core/player_tuning.gd
class_name PlayerTuning extends Resource

const FPS := 60.0

@export var walk_speed_pf        := 1.375   # px/frame ->  82.5 px/s
@export var jump_velocity_pf     := 4.9375  # px/frame -> 296.3 px/s (upward)
@export var gravity_pf           := 0.25    # px/frame^2 -> 900 px/s^2
@export var terminal_velocity_pf := 7.0     # px/frame -> 420 px/s
@export var slide_speed_pf       := 2.5     # px/frame -> 150 px/s
@export var slide_frames         := 26      # -> 65 px of travel
@export var climb_speed_pf       := 1.0     # px/frame ->  60 px/s
@export var knockback_speed_pf   := 0.5     # px/frame, away from the damage source
@export var knockback_frames     := 16
@export var iframes              := 90      # ~1.5 s, sprite flickers every 2 frames
@export var shot_speed_pf        := 5.0     # px/frame -> 300 px/s
@export var shoot_pose_frames    := 16      # how long the firing pose holds

func px_s(v: float) -> float: return v * FPS
func px_s2(v: float) -> float: return v * FPS * FPS
```

Derived values worth asserting in tests: **jump apex = v²/2g = 48.8 px** (≈ 3 tiles) and
**slide distance = 65 px** (≈ 4 tiles). If a level requires a 4-tile jump, the level is
wrong, not the constant.

Variable jump height: on `jump` release while `velocity.y < 0`, set `velocity.y = 0`
outright. Do **not** multiply by a factor — the hard cut is what gives the original its
distinctive short hop.

Ground movement has **no acceleration and no friction.** `velocity.x` is
`direction * walk_speed`, or exactly `0`. Resist the urge to add smoothing.

### Player collision

| State | Shape | Size |
| --- | --- | --- |
| Standing / walking / jumping | `RectangleShape2D` | 16 × 24, origin at feet |
| Sliding | `RectangleShape2D` | 16 × 14, origin at feet |

Swap the shape on slide enter/exit. On slide exit, cast upward 10 px first; if blocked,
stay sliding until there is headroom (this is what makes low tunnels work).

The sprite cell is larger than the hitbox (see SPRITES §2) — never derive collision from
sprite size.

## 4. Collision layers

Godot has 32 2D layers; name all of these in project settings so the inspector is readable.

| Bit | Name | Used by |
| --- | --- | --- |
| 1 | `world` | Solid tiles, walls, doors when sealed |
| 2 | `one_way` | Pass-through platform tiles |
| 3 | `ladder` | Ladder `Area2D`s |
| 4 | `player_body` | Player `CharacterBody2D` |
| 5 | `player_hurtbox` | Where the player *takes* damage |
| 6 | `player_attack` | Buster shots, weapon projectiles, Top-Spin-style contact |
| 7 | `enemy_body` | Enemy bodies (for platforming on them, if any) |
| 8 | `enemy_hurtbox` | Where enemies take damage |
| 9 | `enemy_attack` | Enemy projectiles and contact-damage boxes |
| 10 | `pickup` | Health, ammo, 1UP, E-tank |
| 11 | `hazard` | Spikes, crushers, bottomless-pit sensors — instant death |
| 12 | `trigger` | Room bounds, camera zones, checkpoints, cutscene volumes |
| 13 | `platform` | Moving/disappearing platforms (`AnimatableBody2D`) |

Mask conventions: `player_attack` masks `enemy_hurtbox` + `world`. `enemy_attack` masks
`player_hurtbox` only (enemy shots pass through walls unless a flag says otherwise — many
NES enemy shots do). Nothing masks its own attack layer.

## 5. Core systems

### 5.1 State machine

Node-based, one script per state, because the player has ~9 states with distinct
enter/exit work and this keeps each file under 60 lines and unit-testable.

```
Player (CharacterBody2D)
├── AnimatedSprite2D
├── CollisionShape2D
├── Hurtbox (Area2D, layer player_hurtbox)
├── ShootOrigin (Marker2D)          # repositioned per state
├── HeadroomCast (RayCast2D)        # slide exit check
└── StateMachine (Node)
    ├── Idle   ├── Walk   ├── Jump   ├── Fall
    ├── Slide  ├── Climb  ├── Hurt   ├── Dead
    └── Teleport
```

```gdscript
# scripts/core/state.gd
class_name State extends Node
var host: Node               # injected by StateMachine
func enter(_msg := {}) -> void: pass
func exit() -> void: pass
func physics_update(_delta: float) -> void: pass
func handle_input(_e: InputEvent) -> void: pass
```

`StateMachine.transition_to(name, msg)` calls `exit()`, swaps, calls `enter(msg)`, and
emits `state_changed`. The debug overlay and tests listen to that signal.

**Shooting is not a state.** It is a `shoot_timer` on the player plus an animation-suffix
lookup: `_anim_name() -> "%s%s" % [state_anim, "_shoot" if shoot_timer > 0 else ""]`.
That single decision keeps the state count from doubling.

### 5.2 Damage

```gdscript
# scripts/core/damage_info.gd
class_name DamageInfo extends RefCounted
var amount: int
var source_position: Vector2
var weapon_id: StringName       # &"buster", &"needle", ...
var flags: int                  # STUN, PIERCE, NO_KNOCKBACK
```

`Hitbox` (Area2D) emits a `DamageInfo` on overlap; `Hurtbox` forwards it to a `Health`
component, which applies the per-entity damage table:

```
final = weakness_table.get(entity_id, {}).get(weapon_id, base_damage)
```

Weakness multipliers live in `resources/damage_tables/*.tres` as explicit *absolute*
values, not multipliers — NES games used flat damage tables, and flat values are easier
to balance and to read in a diff.

### 5.3 Health scale

Player and every boss have **28 HP**, matching the original's 28-tick energy bar, so one
bar segment is one HP and the HUD needs no scaling maths. Buster does 1. Weakness weapons
do 2–4. E-tank restores 28. Small health pickup 2, large 10.

### 5.4 Camera and rooms

Scroll-locked rooms, not free scroll.

- A `Room` node owns a `bounds: Rect2i` (in tile units) and a list of exits.
- `Camera2D` limits are set from the active room's bounds; `position_smoothing_enabled`
  is **off**, `ignore_rotation` on.
- Crossing a `Door` trigger runs the transition coroutine: freeze the player, slide the
  camera to the next room over 32 frames, walk the player 24 px through the doorway,
  unfreeze. Enemies in the outgoing room are freed.
- Vertical ladder transitions use the same coroutine with a vertical slide.

### 5.5 Enemy spawn/despawn

Reproduce the original rule exactly, because level design depends on it:

- Each enemy is authored as a `SpawnMarker` in the room, not as an instance.
- A marker spawns its enemy when it enters `camera_rect.grow(16)`.
- The instance is **freed** when it leaves `camera_rect.grow(32)`, and the marker is
  re-armed. Scrolling back and forth therefore yields a fresh enemy every time — that is
  the intended behaviour, and it is what makes farming health drops possible.
- Bosses, mini-bosses, and gimmick platforms opt out via `persistent = true`.

### 5.6 Weapons

```gdscript
# scripts/core/weapon_data.gd
class_name WeaponData extends Resource
@export var id: StringName
@export var display_name: String
@export var projectile_scene: PackedScene
@export var ammo_max: int = 28
@export var ammo_cost: int = 1
@export var max_on_screen: int = 3
@export var fire_cooldown_frames: int = 0
@export var palette: Array[Color]     # 2-colour swap for the player sprite
@export var icon: Texture2D
```

`WeaponManager` (autoload) holds the unlocked set, current selection, and ammo. Palette
swap is a `ShaderMaterial` on the player's `AnimatedSprite2D` that remaps two index
colours — generate the sprite in a fixed 2-tone scheme so this works (SPRITES §3).

### 5.7 Autoloads

| Autoload | Owns |
| --- | --- |
| `GameState` | Bosses defeated, weapons unlocked, E-tanks, lives, current stage, checkpoint |
| `WeaponManager` | Ammo, selection, unlock set (reads/writes `GameState`) |
| `SceneRouter` | Scene changes, fade/teleport transitions, loading |
| `AudioManager` | BGM crossfade, SFX pool, bus ducking for jingles |
| `Tuning` | Loads `PlayerTuning`; exposes debug hot-reload in dev builds |

Keep autoloads free of node references into the active scene — they outlive it.

## 6. Input map

| Action | Keyboard | Gamepad |
| --- | --- | --- |
| `move_left` / `move_right` | ← / → , A / D | D-pad, left stick X |
| `move_up` / `move_down` | ↑ / ↓ , W / S | D-pad, left stick Y |
| `jump` | Z / Space | A (bottom face) |
| `shoot` | X | X (west face) |
| `weapon_prev` / `weapon_next` | A / S , Q / E | LB / RB |
| `pause` | Enter | Start |
| `slide` | — | — |

Slide is **down + jump**, not its own binding — that is the MM3 input and it must stay
that way. Read it as `Input.is_action_just_pressed("jump") and Input.is_action_pressed("move_down")`
inside the grounded states, checked *before* the jump branch.

Deadzone 0.5 on sticks so diagonal drift doesn't trigger slides.

## 7. Import presets

Add to `project.godot` so every sprite imports correctly without per-file clicking:

```ini
[importer_defaults]

texture={
"compress/mode": 0,
"mipmaps/generate": false,
"detect_3d/compress_to": 0,
"process/fix_alpha_border": true
}
```

Nearest filtering comes from the project-wide `default_texture_filter` in §2; the
per-texture `Filter` field was removed from the texture importer in Godot 4 and now lives
on the node / canvas item. If a single sprite ever needs different filtering, set
`texture_filter` on that node rather than reintroducing per-file import overrides.

## 8. Save and password

Two persistence paths, both writing the same struct:

```gdscript
{ "bosses_defeated": 0b00000000,   # 8 bits
  "items_unlocked":  0b000,        # coil / jet / marine
  "etanks": 0,                     # 0-9
  "lives": 2 }
```

- **Save slot:** JSON at `user://save_0.json`, written on stage clear and on quit.
- **Password:** pack the same 12 bits + E-tank count into a 5×5 dot grid
  (25 cells = 25 bits, plenty), with a 4-bit checksum so typos are rejected with a
  "wrong password" buzz instead of a corrupt state. Render as the classic red/blue grid.

Password is cosmetic-retro but cheap; do it in M6, not before.

## 9. Testing

gdUnit4, headless in CI.

- **Tuning tests** (the important ones): simulate the player 60 physics steps and assert
  jump apex, slide distance, terminal velocity, and knockback displacement in pixels.
  These are the regression net for game feel.
- **State machine tests:** assert legal transitions and that no state can be entered
  twice without an `exit()`.
- **Damage table tests:** every boss has exactly one weapon dealing ≥ 2× buster damage;
  no boss is weak to its own weapon; the weakness graph has no isolated node.
- **Resource lint:** every `WeaponData` has a projectile scene; every generated
  `SpriteFrames` contains the animation names the player state machine asks for. This one
  catches the most real bugs — run it after every art regeneration.
